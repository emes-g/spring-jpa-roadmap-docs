## 서블릿과 스프링
### 개념
- **서블릿:**
  - 네트워크를 통해 들어온 HTTP 요청 문자열을 자바 객체(`HttpServletRequest`)로 변환하고, 로직 처리 후 다시 HTTP 응답(`HttpServletResponse`)으로 변환하여 반환하는 자바 클래스이다.
  - 즉, **HTTP 요청을 받아서 처리하고, 응답을 만들어내는 자바 객체**이다.
  - 예) `DispatcherServlet`
- **서블릿 컨테이너:**
  - 톰캣같은 **웹서버 구동 프로그램 그 자체**이다.
  - 네트워크 포트를 열고 **클라이언트의 연결을 수신**하며, **서블릿/서블릿 필터 객체의 생명주기(생성, 실행, 소멸)를 관리**한다.
  - 다수의 클라이언트 요청을 처리하기 위해, 요청마다 스레드를 할당하는(Thread Per Request) **멀티 스레드 환경을 제어**한다.
- **서블릿 컨텍스트:**
  - **서블릿 컨테이너(톰캣)의 동작에 필요한 정보(URL 매핑 정보, 공유 데이터 등)를 저장하는 객체(메모리 공간)로, 메모리에 단 1개만 생성된다.**
- **스프링 컨테이너:**
  - **스프링 빈의 생성, 등록, DI, 생명주기를 관리**한다.
  - 또한 AOP 및 트랜잭션을 처리하며, 이외에도 다양한 부가 기능을 가지고 있다.

### 전통적인 방식에서의 관계 (웹 서버 주도)
- **과거에는 개발자가 외부 톰캣 서버를 직접 설치하고, 그 위에 개발한 코드를 얹어 실행했다.**
- **실행 주체:** 서블릿 컨테이너(톰캣)
- **실행 순서:**
  - 톰캣 실행 → 웹 애플리케이션 구동을 위해 `ServletContext` 생성 → 내부 설정 파일(`web.xml`)을 읽어 스프링 컨테이너 생성
- **특징:**
  - `ServletContext`(웹 환경 객체) 내부에 스프링 컨테이너가 데이터(Attribute)의 형태로 적재되어 동작한다.

### 스프링 부트 방식에서의 관계 (스프링 주도)
- **현재 사용하는 스프링 부트는 톰캣 라이브러리를 내장하고 있다.**
- **실행 주체:** 자바의 `main()` 메서드 (스프링 애플리케이션)
- **실행 순서:**
  - 자바 프로그램 실행 → 스프링 컨테이너 먼저 생성 → 스프링이 내부적으로 내장 톰캣(서블릿 컨테이너) 구동 → 톰캣이 구동되며 `ServletContext` 생성
  - 이때 웹 MVC 라이브러리가 존재함이 확인되면, 웹 전용 스프링 컨테이너인 `AnnotationConfigServletWebServerApplicationContext` 객체를 생성한다.
- **특징:**
  - 스프링 컨테이너가 애플리케이션의 최상위 실행 주체다.
  - 톰캣과 서블릿 컨텍스트는 스프링 컨테이너가 생성하고 제어하는 컴포넌트로 위치가 완전히 역전되었다.

### @SpringBootApplication 실행 시 발생하는 일
1. **자바 메인 메서드 실행:**
   - `SpringApplication.run()`이 호출된다.
2. **스프링 컨테이너 생성:**
   - 일반 컨테이너(`AnnotationConfigAC`)가 아닌 웹 전용 컨테이너(`AnnotationConfigServletWebServerAC`) 객체가 생성된다.
3. **내장 톰캣 생성 및 실행:**
   - 생성된 스프링 컨테이너가 초기화되는 과정에서, 내장된 톰캣 객체를 생성하고 네트워크 포트(8080)를 열어 실행시킨다.
4. **서블릿 컨텍스트 생성:**
   - 내장 톰캣이 실행되면서 웹 동작 환경 객체인 `ServletContext`가 메모리에 만들어진다.
5. **DispatcherServlet 등록:**
   - 스프링은 들어오는 모든 HTTP 요청을 받을 유일한 진입점인 `DispatcherServlet` 객체를 생성하여, `ServletContext`에 서블릿으로 등록한다.
   - 이를 통해 톰캣(서블릿 컨테이너)과 스프링 컨테이너가 연결된다.
6. **스프링 빈 생성 및 DI:**
   - 스프링 컨테이너가 싱글톤 빈(컨트롤러, 서비스 등 비즈니스 로직 관련)을 생성하고 DI한다.
7. **수신 대기:**
   - 톰캣 서버가 클라이언트의 HTTP 요청을 받을 준비를 마친다.

### 서블릿 컨테이너 vs 서블릿 컨텍스트
> **동작은 컨테이너가 수행하며, 동작에 필요한 정보(URL 매핑 정보, 공유 데이터 등)는 컨텍스트에 저장한다.**

#### 서블릿 컨테이너 (실행 주체 / 프로세스)
- 실제로 CPU를 점유하며 구동되는 서버 프로그램(프로세스)이다.
- 설정한 포트로 들어오는 **HTTP 통신을 수신**하고, 다수의 요청을 처리하기 위해 **스레드를 생성**하며, **서블릿 객체의 로직을 직접 호출하여 실행**한다.

#### 서블릿 컨텍스트 (데이터 저장소 / 정적 메모리 객체)
- 컨테이너가 실행 능력을 가진 프로그램이라면, 컨텍스트는 **컨테이너가 자신의 메모리 영역에 생성해 둔 데이터 저장용 객체**일 뿐이다. 스스로 무언가를 실행할 수 없다.
- **어떤 URL 요청이 들어오면 어떤 서블릿을 실행해야 할지**(특별히 설정하지 않았다면 `DispatcherServlet`)를 나타내는 URL 매핑 정보와 **애플리케이션 전체가 공유할 전역 설정값**을 저장해둔다.
- 즉, **컨테이너(프로세스)는 요청이 들어오면 컨텍스트(객체)의 내부 데이터를 읽고 판단하여 알맞은 서블릿을 실행**한다.
