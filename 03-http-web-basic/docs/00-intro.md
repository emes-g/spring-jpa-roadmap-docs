## 강의 목표
> **모든 웹 서비스는 HTTP 위에서 동작하므로, HTTP의 전체 흐름을 이해하는 것**이 목표이다.

---

## 강의 흐름
### 1. 인터넷 네트워크 (하부 인프라)
- **상위 애플리케이션 계층의 HTTP는 하위 전송 계층인 TCP/UDP 및 IP 프로토콜 기반 위에서 동작**한다.
- 따라서 HTTP에 앞서, 복잡한 인터넷 망에서 데이터가 라우팅되는 방식과 프로토콜 계층 구조에 대한 이해가 선행되어야 한다.
- **TCP/IP** 모델의 기본 개념, 신뢰성 있는 연결 수립을 위한 **TCP 3-Way Handshake**, 그리고 도메인을 IP 주소로 변환하는 **DNS**의 역할 먼저 파악한다.

### 2. URI와 웹 브라우저 요청 흐름
- 하부 인프라를 바탕으로, 실제 브라우저에 URL을 입력했을 때 발생하는 전체 동작 주기를 살펴본다.
- 브라우저가 HTTP 요청 메시지를 생성하면, 하위 **TCP/IP 계층에서 이를 캡슐화하여 네트워크 패킷으로** 만든다.
- **이 패킷이 인터넷을 거쳐 서버로 전송**되고, **서버가 처리 후 응답을 반환하면 최종적으로 브라우저가 파싱하여 화면에 렌더링**하는 흐름이 이어진다.

### 3. HTTP 기본 특성
- HTTP는 클라이언트와 서버의 역할을 분리하는 **클라이언트-서버 구조**를 가진다.
- 특히 **서버가 클라이언트의 상태를 기억하지 않는 무상태성(Stateless)과 통신 직후 연결을 끊는 비연결성(Connectionless)을 갖는다**는 것이 가장 중요한 특징이다.
- 무상태성은 서버의 무한한 확장성(Scale-out) 확보와 직결되므로, 상태 유지(Stateful) 통신과 비교하여 그 매커니즘을 상세히 다룬다.
- 이러한 특징을 기반으로 단순하고 확장 가능한 HTTP 메시지의 구조적 규격을 확인한다.

### 4. HTTP 메서드 및 데이터 전송
- **단일 API URI만으로는 리소스에 대한 행위를 구분하기 어렵다**는 설계적 문제점 때문에 **HTTP 메서드가 도입**되었다.
- 각 메서드의 종류와 동작 방식, 그리고 **안전성, 멱등성, 캐시 가능성** 등의 속성을 정의하여 목적에 맞게 사용하는 법을 학습한다.
- 클라이언트는 쿼리 파라미터(`GET`), HTML 폼 전송(`application/x-www-form-urlencoded`), HTTP API(JSON) 방식을 통해 서버로 데이터를 전달한다.
- 이를 바탕으로 좋은 API URI를 설계하는 패턴을 배운다.

### 5. HTTP 상태 코드 및 헤더
- 클라이언트의 요청에 대한 **서버의 처리 결과는 3자리 숫자인 상태 코드로 명세되어 반환**된다.
- HTTP 헤더는 **콘텐츠 네고시에이션, 데이터 분할 전송 등 메타데이터와 부가 기능을 제어**하는 역할을 수행한다.
- **무상태성 통신 환경에서 예외적으로 클라이언트의 상태 데이터를 일부 유지해야 할 필요성**이 생기며, 이를 해결하기 위해 **쿠키** 매커니즘이 사용된다.

### 6. HTTP 캐시
- 불필요한 네트워크 통신을 최소화하고 성능을 최적화하기 위해 브라우저 캐시와 프록시 캐시가 도입되었다.
- **캐시를 적용할 때 서버 데이터와의 정합성이 깨질 수 있으며**, 이를 해결하기 위해 **특정 상황에서 캐시를 강제로 무효화(Cache Invalidation)하는 헤더 제어 기법**을 배운다.

### 복습
#### 웹 개발에서 HTTP 지식이 중요한 이유
> **HTTP는 클라이언트와 서버가 데이터를 주고받는 웹 애플리케이션 통신의 기본 규약이기 때문이다.**

#### HTTP의 주요 특징인 무상태성의 의미
> **각 요청이 독립적으로 처리되며, 이전 요청과의 연결 상태를 유지하지 않는다.**

#### HTTP 메서드의 역할
> **클라이언트가 서버의 특정 리소스에 대해 원하는 동작을 정의**한다.

#### HTTP 헤더와 캐싱 매커니즘이 웹 통신의 효율성에 기여하는 방식
> **헤더를 통해 통신에 필요한 부가 정보를 전달**하고, **캐싱을 통해 응답 시간을 단축하고 부하를 줄일 수 있다.**
